Privacy notice

Your sources, used for your own assistant.

Effective 23 October 2026

This notice describes the local application and the optional Google connections named Chris AI Gmail and Chris AI YouTube. They are parts of Chris AI Personal Assistant, an application operated by its owner for personal use.

This public site provides application information only. It has no sign-in, upload form, advertising, analytics script, or tracking cookie. A hosting provider may process ordinary connection logs under its own policies; the assistant's private data is not uploaded to this site.

1. Data accessed and collected

Google data is accessed only after the account owner explicitly authorizes the corresponding connection. The owner chooses which source to enable.

  • Gmail: message bodies and snippets; subjects; sender and recipient headers; message dates; label, thread, and message identifiers. An initial bounded date range and later incremental changes are read using https://www.googleapis.com/auth/gmail.readonly.
  • YouTube: channel identifiers used to check account identity; subscriptions; liked-video metadata; and items from playlists selected by the owner. Metadata may include titles, descriptions, channel names, links, identifiers, and available dates. The scope is https://www.googleapis.com/auth/youtube.readonly. Watch history is not available through this API connection.
  • Authorization and operation: OAuth client configuration and refresh credentials, synchronization cursors, a hashed account-identity fingerprint, source status, and bounded usage or error records.
  • Other owner-selected context: the application may combine Google records with goals, background, tasks, files, or other sources the owner separately supplies or authorizes. It also stores resulting suggestions, evidence links, feedback, and local memories.

The Google connectors use read-only APIs. They do not request Google passwords, send or modify Gmail messages, or change the account's YouTube activity.

2. How the application uses data

Data is used to provide the owner's personal assistant: local search, source-linked summaries, information recommendations, task and communication preparation, and decision support. A single view, like, or subscription is not treated as a confirmed long-term preference.

Google user data is not sold, rented, used for advertising, or provided to data brokers. The application does not use Google user data to develop, improve, or train general-purpose AI or machine-learning models. Local feedback changes the assistant's stored context; it does not train model weights.

Google data is to be used only for the user-facing functions described here, consistent with the Google API Services User Data Policy, including its Limited Use requirements. This statement describes the application's data-use restriction; it is not a statement that Google has verified or approved the application.

3. External processing and sharing

Local storage does not mean all analysis is offline. When cloud analysis is enabled, the application selects bounded, relevant source excerpts together with necessary goals, context, and instructions. It attempts to replace identity details and remove sensitive URL parameters before sending them. This filtering is not complete anonymization and may miss sensitive information.

  • Configured AI service: the current implementation supports Codex through the owner's ChatGPT subscription, operated by OpenAI, and optional DeepSeek processing. DeepSeek is used only when the owner explicitly selects it or enables the supported paid backup. The configured provider receives the request fragments and produces analysis.
  • Telegram: if the owner binds and enables a personal bot, Telegram receives selected summaries, replies, and notifications. When the owner explicitly asks to view a source, limited source text, including saved email text, may also be sent. Files or text the owner sends to the bot are already processed by Telegram before the assistant receives them.
  • Google: Google's authorization and API services process account authorization and the read-only requests needed for synchronization.

There is no public sharing feature or advertising integration. These services operate under their own terms, account settings, retention practices, and applicable requirements. This application cannot promise that a third-party service retains nothing, never permits human access, or can recall all previously transmitted data. Provider settings and eligibility must be reviewed before enabling processing of Google user data; this notice does not override provider terms.

4. Local storage and retention

Collected records, search indexes, evidence, suggestions, feedback, tasks, and memories are stored on the owner's computer. They are retained until the owner deletes them; there is no general automatic expiry for source content. OAuth credentials are stored encrypted, with the encryption key protected for the local operating-system user. The database and all content files are not represented as fully encrypted storage.

The assistant's web service is configured to listen on the local loopback interface. Access to the computer, operating-system account, local backups, and any exported copies remains the owner's responsibility. Backups can contain personal records; a complete local backup can also contain encrypted credentials.

5. Pause, revoke, and delete

  1. Stop collection: disable the relevant source in the local assistant's Settings. Pausing synchronization does not delete previously collected records.
  2. Revoke Google access: remove the corresponding app from the Google Account's third-party connections. The local assistant also provides a credential-revocation control that clears the saved authorization credential and disables the source; it does not itself revoke the grant at Google. Neither action automatically deletes the local index.
  3. Delete local data: use the assistant's data-deletion controls to select a source, person, date range, individual item, or all records. Deletion clears matching current and historical source content and search entries, linked suggestions and tasks, associated queued work, saved conversations, and pending notifications. A derived memory supported only by deleted evidence is removed; a memory with other evidence is marked for review.

Managed original files are deleted as part of cleanup. A file locked by another program may remain pending until a later cleanup attempt. Non-reversible deletion fingerprints are retained to prevent ordinary automatic re-import; an explicit re-import or backup restoration can recreate records.

Local deletion does not delete messages from Gmail, change YouTube, erase an external source file, remove a separate backup, or recall messages already sent to Telegram or an AI provider. Copies held by another service or previously exported by the owner require separate handling. Data already sent to a provider may be subject to that provider's retention and deletion process.

6. Requests and changes

The application is operated by its account owner and is not offered as a public multi-user service. The owner can inspect sources, correct information, pause collection, and initiate deletion from the local application. This information site does not accept private documents or account requests.

If the application is offered to additional users or its processing changes, the maintainer must review this notice, provide a suitable support contact, and complete any additional Google policy or verification requirements before that expanded use. The revision date will be updated when this notice changes.
